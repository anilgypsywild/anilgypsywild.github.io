Research article

Learning Cause Affinity via Supervised Multiclass Classification

Bounded Exploratory POC for UX, Product, and Design Review

Signal Tags: 🤖 Machine Learning · 📊 Statistical Ranking · 🌳 Interpretable Rules · 🧭 UX Decision Support

Author: @AShankar5
Scope: Exploratory feasibility only
Initial Review Format: 20-minute team huddle / design review
Project Type: Research-grounded statistical learning proof of concept

1. Purpose Of This Brief

This document reframes the original cause-affinity ML feasibility work as a design-support and product-support POC.

The goal is not to argue for immediate implementation.

The goal is to evaluate whether a lightweight recommendation layer could improve the first-view Causes experience by helping the page surface the three most relevant cause paths first.

Core boundary

  • This is not “AI instead of design.”
  • This is not a request for immediate engineering work.
  • This is a bounded exploratory assessment of whether a recommendation layer is worth keeping in exploratory scope.

2. Product Problem Being Addressed

Core product question

When a visitor lands on the Causes experience, which three cause types should they see first?

Why this matters

The current Causes surface asks users to interpret:

  • category labels
  • country / project metadata
  • fundraising state
  • visual content
  • descriptive copy

before the page clearly answers:

“What is this, why does it matter, and what should I look at first?”

This creates a first-view UX and information-architecture problem:

  • too many competing signals
  • too little guidance
  • too much translation work left to the user

Executive alignment with the broader portfolio direction

This concept directly supports the broader multi-product direction described in the recent all-hands portfolio framing:

  • Not every supporter is motivated by the same thing, and not every moment calls for the same response.
  • A strong product portfolio offers multiple entry points.
  • Products should work together, not compete for attention.
  • The portfolio should create pathways from lower-commitment entry into deeper engagement.
  • It is not about variety alone; it is about intentional design and clarity.
  • The real risk is not multiple offerings; it is multiple offerings without clarity.

Taken together, those leadership principles imply a practical UX problem:

If the portfolio offers multiple valid ways in, the first view must help users see the most relevant entry points without forcing them to decode the full system on their own.

This is why the recommendation concept matters. It is not adding more complexity to the portfolio. It is one way to make the portfolio:

  • easier to understand at the point of entry
  • more personally relevant
  • less cognitively overwhelming
  • more aligned to the stated goal of meeting supporters where they are

Proposed intervention

A recommendation layer can help the page:

  • lead with the most relevant cause path first
  • reduce cognitive load
  • improve clarity at the point of entry
  • support both new and returning visitors differently

3. Research Objective

Item Description
Core Question Can observable visitor signals support a ranked first-view recommendation that is more relevant than a static default ordering?
Business Framing Can the first-view Causes experience make the broader multi-product portfolio feel clearer, more intentional, and more personally relevant by surfacing the three most relevant cause paths first?
Learning Task Supervised multiclass ranking / classification
Output Predicted probability distribution over K cause categories, used to rank the first three shown
Primary UX Outcome Improved first-view relevance and reduced interpretation burden
Primary Quant Metric Top-3 Accuracy / Top-3 relevance
Decision Variable Lift over static frequency baseline
Immediate Decision Keep in exploratory scope, refine further, or pause

4. Formal Learning Setup

Component Definition
Input Space X = visitor/session feature vector
Label Space Y = cause category or cause path label
Training Sample S = labeled session examples
Hypothesis f(x) = estimated probability vector over cause categories
Served Output Ranked top-3 categories from f(x)
UX Action Reorder first-view cause paths and first-view cause cards

First-view ranking interpretation

X ⊂ ℝd,  Y ∈ {1, 2, …, K},  S = {(xi, yi)}i = 1n

f(x) = [p1(x), p2(x), …, pK(x)]  where  pk(x) = P(Y = k ∣ X = x)

$$\sum_{k=1}^{K} p_k(x) = 1$$

The product uses the three largest probabilities to determine which three cause paths should lead the first view:

Top3 (f(x))

Primary evaluation metric

$$\operatorname{Top3Acc} = \frac{1}{n} \sum_{i=1}^{n} \mathbf{1}\!\left\{ y_i \in \operatorname{Top3}(f(x_i)) \right\}$$

Where:

  • I[...] is the indicator function
  • it equals 1 if the true category appears in the model's top 3
  • it equals 0 otherwise

Lift over baseline

Lift  = Top3Accmodel − Top3Accbaseline

5. UX And Product Interpretation

The statistical output is not the final user experience.

The output is translated into a page-level intervention:

$$\text{Visitor Signals} \rightarrow \text{Ranked Cause Types} \rightarrow \text{Ordered First\text{-}View Content}$$

What changes in the experience

  • which cause path leads first
  • which cause cards fill the first visible slots
  • which framing leads the page (urgency, clarity, development, community impact)

What does not need to change immediately

  • the full content system
  • the full taxonomy
  • the full page architecture
  • the donation flow

POC value

This is why the concept is attractive:

  • it changes sequencing, not the whole system
  • it is testable
  • it can remain bounded
  • it gives design a concrete way to improve clarity without redesigning everything first

6. Cold Start And Warm Start

The same framework supports both new and known visitors.

Visitor State Available Signal POC Value
Cold Start Referral source, device, geography, session behavior, page interactions Helps guide new visitors who arrive with limited context
Warm Start Session behavior + prior cause engagement + prior giving / interaction history Helps returning users see more relevant and deeper next steps

Cold-start requirement

The POC must be viable under minimal features:

Xcold = {session context, device, referral source, lightweight behavior}

Warm-start enhancement

Xwarm = Xcold ∪ {history, recency, prior category engagement}

This matters because the recommendation layer is most valuable when it can improve the experience even at first exposure.

8. Baseline And POC Model Classes

8.1 Static Baselines

Baseline Description Purpose
Baseline 1 Predict globally most frequent category Minimum unpersonalized reference
Baseline 2 Predict globally top-3 categories Static “one-size-fits-most” ranking reference

These represent what the product is effectively doing if no visitor-specific inference is used.

8.2 Primary Predictive Model 🤖

Component Specification
Model Multinomial Logistic Regression
Output Probability distribution over cause categories
Regularization L2 penalty
Purpose Interpretable probability ranking baseline

Why logistic regression first

Design-friendly explanation:

  • it gives each cause path a score
  • converts those scores into probabilities
  • returns a ranked list the page can use directly

$$P(Y = k \mid x) = \frac{\exp(\beta_k^\top x)} {\sum_{j=1}^{K}\exp(\beta_j^\top x)}$$

Where:

  • beta_k is the coefficient vector for class k
  • x is the visitor/session feature vector
  • the denominator normalizes the scores into probabilities that sum to 1

This makes it a strong first model for a page that needs:

  • first choice
  • second choice
  • third choice

8.3 Interpretation Layer 🌳

Model Purpose Notes
Shallow Decision Tree Explain routing logic in readable rules High interpretability, lower complexity

Why include a tree

The tree is not necessarily the best ranking model.

It is valuable because it creates a readable explanation such as:

  • if visitor is new and trust-seeking, lead with foundational needs
  • if visitor is returning and development-oriented, lead with long-term opportunity

That helps UX, PM, and design understand why the first view changes.

9.4 Statistical Confidence

Method Description
Bootstrap Resampling Estimate variability of lift
Confidence Interval 95% CI for lift using bootstrap standard error
Significance Criterion CI excludes zero lift

Bootstrap confidence interval form:

$$\widehat{\operatorname{Lift}} \pm 1.96 \cdot SE_{\text{boot}}(\widehat{\operatorname{Lift}})$$

10. Success Criteria

Criterion Threshold
Top-3 Lift Meaningful positive lift over static top-3 baseline
Stability Low resample variance / no collapse under repeated evaluation
Explainability Model can be translated into understandable page-level logic
Cold-Start Performance Above baseline with lightweight visitor features

Failure condition

The POC should be treated as insufficient if:

  • performance stays within baseline uncertainty
  • the first-view ranking does not meaningfully differentiate visitors
  • the output is too unstable or too opaque to support product use

12. Theoretical Framing

Cause ranking at the first view is not only a design choice.

It is also a statistical inference question:

Does the available feature space contain enough structure to improve first-view ranking beyond a static default?

If the answer is yes, then first-view ordering becomes a learnable inference function.

If the answer is no, then static ordering remains the more defensible product default.

This POC evaluates that boundary.

Formal risk framing

The relevant question is whether we can reduce top-3 misranking risk:

RTop3(f) = 𝔼[1 {Y ∉ Top3 (f(X))}]

The POC asks whether:

RTop3(fmodel) < RTop3(fbaseline)

in a stable, interpretable, and UX-meaningful way.

13. Why This Matters For Design And Product

This POC is worth pursuing because it converts a vague personalization idea into a bounded design-support question:

  • Can we reduce interpretation burden at the first view?
  • Can we make the first three choices feel more intentional?
  • Can the page meet different visitor states more appropriately?

The immediate contribution is not “AI.”

The immediate contribution is:

  • clearer sequencing
  • less flat browsing
  • better first-view guidance
  • a way to make the portfolio easier to navigate

This also makes the concept strategically relevant beyond the Causes page itself.

If the organization is serious about a multi-product portfolio with:

  • multiple entry points
  • different giving pathways
  • stronger fit to different supporter motivations

then the first-view experience cannot remain a flat, one-size-fits-all default indefinitely.

As the portfolio expands, the cost of poor first-view sequencing rises:

  • users face more interpretation burden
  • products compete more visibly for attention
  • the path into deeper engagement becomes less intentional

In that sense, this POC is not separate from the portfolio strategy. It is one practical mechanism for making that strategy usable at the point of entry.

That is why this is worth evaluating even before any implementation decision.

14. Immediate Recommendation

Proceed with this as a bounded exploratory POC only if the team agrees the immediate question is:

Is this worth keeping in exploratory scope long enough to validate properly?

That is the decision this brief supports.

Not:

  • shipping
  • committing engineering work
  • replacing design
  • claiming production-ready personalization

This is an evidence-building step.

Practical takeaway from these references

Across these texts, the recurring themes are the same:

  • separate exploratory signal from decision-grade evidence
  • match model choice to the decision interface
  • evaluate lift relative to a baseline, not in isolation
  • justify complexity through stable generalization, not novelty
  • avoid over-claiming from weak or confounded evidence
