Critical User Journeys for Causes

User Story 1: Discovering a Cause

As a potential donor, I want to explore different causes on the platform, so that I can find one that aligns with my values and interests.

JTBD: When I want to donate to a cause, I need an easy way to browse and filter different options, so that I can confidently support a cause that aligns with my personal values.

  • Entry Point: Homepage / Search Bar / Filter Menu
  • Key Actions:
    • Browse categories of causes
    • Use filters to refine search (e.g., health, education, emergency relief)
    • View cause details
  • Success Criteria: User successfully identifies a cause of interest.

User Story 2: Understanding Cause Details and Transparency

As a donor, I want to see clear information about how my donation will be used, so that I can feel confident in my decision to give.

JTBD: When I consider donating, I need clear and transparent information about fund allocation, so that I feel assured that my donation is making a meaningful impact.

  • Entry Point: Cause Details Page
  • Key Actions:
    • Read the cause description
    • Check fund allocation breakdown
    • View impact stories or updates
  • Success Criteria: User gains trust and understanding of how funds are used.

User Story 3: Making a Donation

As a donor, I want to complete a donation process smoothly, so that I can contribute to a cause without frustration.

JTBD: When I decide to donate, I need a simple and quick process to complete my contribution, so that I don’t feel frustrated or discouraged from giving.

  • Entry Point: Cause Details Page > Donate Button
  • Key Actions:
    • Select donation amount
    • Choose payment method
    • Review and submit payment
  • Success Criteria: User completes donation without errors or confusion.

User Story 4: Navigating and Using Filters

As a donor, I want to use filters effectively, so that I can quickly find a cause that aligns with my giving preferences.

JTBD: When looking for a cause, I need filtering options that help me narrow down choices efficiently, so that I can quickly find a cause that resonates with me.

  • Entry Point: Homepage / Search Results Page
  • Key Actions:
    • Apply filters by category, urgency, or impact area
    • Modify search parameters if needed
    • Reset filters if results are not relevant
  • Success Criteria: User refines search and finds a relevant cause efficiently.

User Story 5: Tracking the Impact of My Donation

As a donor, I want to receive updates on how my donation was used, so that I feel engaged and reassured about my contribution.

JTBD: After donating, I need to receive updates about the impact of my contribution, so that I feel connected and encouraged to donate again.

  • Entry Point: Post-Donation Confirmation Page / Email Notification
  • Key Actions:
    • Open and review donation receipt
    • Check updates on the supported cause
    • Read success stories related to donation impact
  • Success Criteria: User feels informed and encouraged to donate again.

User Story 6: Trust Validation Through Testimonials and Ratings

As a new donor, I want to see testimonials and ratings from other donors, so that I can determine if the platform is trustworthy.

JTBD: When deciding to donate, I need to see credible testimonials and ratings, so that I can trust that my contribution will be used effectively.

  • Entry Point: Cause Details Page / Testimonials Section
  • Key Actions:
    • Read donor testimonials
    • View trust indicators (e.g., verified partnerships, impact statistics)
    • Engage with social proof elements
  • Success Criteria: User gains trust and confidence in the platform.

User Story 7: Handling an Unexpected Scenario (Catch Trial)

As a donor, I want to find a specific type of cause that does not exist, so that I can test how the platform handles search failures.

JTBD: When searching for a cause, I need clear feedback if my search query does not return results, so that I understand what alternative actions I can take.

  • Entry Point: Search Bar / Filter Menu
  • Key Actions:
    • Enter a cause type that is not available
    • Observe error handling or suggested alternatives
  • Success Criteria: User encounters and evaluates the platform’s failure-handling mechanisms.

Appendix: Understanding User Stories and JTBD

What is a User Story?

A User Story is a short, simple description of a feature told from the perspective of the user. It follows the format:

As a [user], I want to [action], so that I can [goal].

User stories help teams understand who the user is, what they need, and why it matters.

📖 Recommended Reading: User Story Mapping by Jeff Patton

What is a Job To Be Done (JTBD)?

A Job to Be Done (JTBD) is a framework that shifts the focus from the user’s intent to the actual problem they are trying to solve. It is written as:

When I [situation], I need [job], so that I can [outcome].

JTBD helps teams innovate and prioritize features based on the real needs of users.

📖 Recommended Reading: Competing Against Luck: The Story of Innovation and Customer Choice by Clayton Christensen

Why This is Useful for research team

Understanding User Stories and JTBD is essential for because it helps align the product with donor needs and motivations. These frameworks ensure that:

  • Product Teams prioritize features that solve real user problems.
  • Designers create intuitive and goal-driven experiences.
  • Researchers measure usability based on clearly defined tasks.
  • Stakeholders have a structured approach to evaluating platform success.
  • Data-Driven Persona Development is strengthened by incorporating quantified user behavior insights, ensuring that the research is not only qualitative but also supported by robust survey and behavioral data.
  • Telemetry & Analytics (MixPanel, FullStory, etc.): By aligning User Stories and JTBD with analytics platforms, can track user journeys, identify friction points, and define event-based signals to trigger real-time intercept surveys. This enables deeper insights into:
    • Engagement Metrics (time spent, clicks, drop-offs)
    • Retention Patterns (repeat visits, donation frequency)
    • Happiness & Frustration Signals (user hesitations, rage clicks, exit paths)
    • Personalized Intervention Triggers (prompting surveys based on specific behaviors)

By integrating User Stories and JTBD into data analytics workflows, can optimize product experiences dynamically, ensuring continuous improvement in engagement and retention strategies.

Final Note

These user stories and JTBD outline the core journeys donors take while navigating Compassion Causes. Understanding these journeys allows us to measure usability effectiveness, trust, and engagement in a structured way.

Research Suggestions to expand Causes User Journeys

1. Expand User Story for Returning Donors

Current Gap: The document primarily focuses on first-time donors. A user story and JTBD for returning donors who want to track their donation history or repeat a donation could be valuable.

Suggested Additions:

  1. User Story: As a returning donor, I want to easily access my donation history, so that I can track my contributions and make repeat donations effortlessly.
    • JTBD: When I want to donate again, I need a simple way to view my past contributions, so that I can quickly support causes I trust without re-entering all my information.
    • Source: Causes_ User Experience (UX) Score Card, Dec '24.pdf
  2. User Story: As a returning donor, I want reminders about causes I previously supported, so that I can continue my impact.
    • JTBD: When I have donated before, I need a reminder system that informs me about the cause’s progress, so that I can decide if I want to contribute again.
    • Source: Causes_ Post Production Research Brief.pdf
  3. User Story: As a donor, I want to receive tailored thank-you messages and updates, so that I feel recognized and valued for my contributions.
    • JTBD: When I give, I need personalized acknowledgment and progress updates, so that I feel appreciated and stay engaged with the cause.
    • Source: N2N (P2P) Sandbox Survey Results, Dec '24.pdf

2. Improve Trust & Security Elements

Current Gap: The trust validation section is focused on testimonials but does not explicitly mention security-related features such as encryption, fraud prevention, or verified nonprofit status.

Suggested Additions:

  1. User Story: As a security-conscious donor, I want assurance that my donation is secure, so that I can confidently provide payment information.
    • JTBD: When making a donation, I need clear verification of secure transactions, so that I feel protected from fraud or misallocation of funds.
    • Source: Causes_ ThematicAnalysis UserConcerns, 2024 Dec.pdf
  2. User Story: As a new donor, I want to see third-party certifications for the platform, so that I can trust that my money is going to a legitimate cause.
    • JTBD: When donating for the first time, I need to see official certifications or external endorsements, so that I feel confident in my choice to contribute.
    • Source: Causes_ Improving Donor Engagement and Usability, Jan '25.pdf
  3. User Story: As a donor, I want to review fraud protection policies, so that I can understand what safeguards are in place.
    • JTBD: When donating online, I need clear fraud protection policies, so that I can trust that my financial details are safe.
    • Source: Causes_ Core Flows Usability Research Nov '24.pdf

3. Optimize for Mobile Users

Current Gap: The document does not explicitly cover how mobile experiences may differ, particularly in terms of navigation, filtering, and payment flows.

Suggested Additions:

  1. User Story: As a mobile user, I want an easy-to-use donation interface, so that I can complete transactions quickly on my phone.
    • JTBD: When donating on mobile, I need an optimized checkout process, so that I can contribute without frustration.
    • Source: Causes_ User Experience (UX) Score Card, Dec '24.pdf
  2. User Story: As a mobile user, I want larger, tap-friendly buttons, so that I can navigate the platform without misclicking.
    • JTBD: When using my phone, I need responsive UI elements, so that I can browse and donate easily.
    • Source: N2N_ Personas Survey Plan Dec '24.pdf
  3. User Story: As a donor, I want autofill options for my payment details on mobile, so that I can complete transactions efficiently.
    • JTBD: When donating, I need secure autofill capabilities, so that I can enter my information quickly and accurately.
    • Source: Causes_ Post Production Research Brief.pdf

4. Highlight Personalization Features

Current Gap: There is no mention of features such as saved causes, personalized recommendations, or cause updates based on donor history.

Suggested Additions:

  1. User Story: As a donor, I want to save my favorite causes, so that I can easily revisit and donate later.
    • JTBD: When browsing causes, I need a save feature, so that I can keep track of the ones I care about.
    • Source: Causes_ ThematicAnalysis UserConcerns, 2024 Dec.pdf
  2. User Story: As a user, I want recommendations based on my giving history, so that I can discover new causes aligned with my interests.
    • JTBD: When I return to the platform, I need relevant suggestions, so that I can continue to make impactful donations.
    • Source: N2N_ FundRaising Research Needs.pdf
  3. User Story: As a donor, I want notifications for time-sensitive campaigns that match my interests, so that I don’t miss urgent opportunities to give.
    • JTBD: When a new campaign aligns with my giving patterns, I need timely alerts, so that I can contribute at the right moment.
    • Source: Causes_ Improving Donor Engagement and Usability, Jan '25.pdf

5. Tie User Stories & JTBD to A/B Testing & Analytics

Current Gap: While there is a section on telemetry and analytics, it does not explicitly mention how these user stories can drive A/B testing and metric evaluation.

Suggested Additions:

  1. User Story: As a product manager, I want to use user journey data to test different experiences, so that I can optimize conversion rates.
    • JTBD: When analyzing engagement, I need structured testable insights, so that I can iterate improvements effectively.
    • Source: Causes_ Post Production Research Brief.pdf
  2. User Story: As a UX researcher, I want to track drop-off points in the donation process, so that I can identify usability issues.
    • JTBD: When evaluating usability, I need analytics on donation abandonment, so that I can refine the user flow.
    • Source: N2N (P2P) Sandbox Survey Results, Dec '24.pdf
  3. User Story: As a data analyst, I want real-time engagement signals to trigger surveys, so that I can gather qualitative insights at key moments.
    • JTBD: When tracking behavior, I need dynamic survey triggers, so that I can capture user sentiment in real-time.
    • Source: Causes_ Improving Donor Engagement and Usability, Jan '25.pdf

Final Thoughts

These refinements will make the Compassion Causes User Journeys document more comprehensive, addressing returning donors, trust concerns, mobile optimization, personalization, and analytics-driven improvements. Implementing these changes will ensure a more data-driven and user-centric approach to platform enhancements.
