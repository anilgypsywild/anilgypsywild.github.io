How to Conduct a Heuristic Review for the Causes App

  • This document serves as a step-by-step guide for conducting a heuristic review of the Causes App, ensuring consistency, usability, and trustworthiness in the donor experience.
  • It builds on Ben Shneiderman’s Eight Golden Rules and incorporates research-driven enhancements to prioritize findings, track progress, and link heuristics to real user feedback.

Re-Use (Do Not Modify) This Template

1️⃣ Setting Up the Heuristic Review

A. Define the Scope of Evaluation

  • Review critical user journeys (Cause Discovery, Donation Flow, Impact Tracking, etc.).
  • Focus on usability, trust, navigation, and donation completion.
  • Use real user feedback from usability tests or support tickets.

B. Tools Needed

✅ GitLab – Track heuristic findings as issues with labels and milestones.
✅ Spreadsheet (Excel/CSV) – Document heuristics in a structured format.
✅ UserZoom or FullStory – Identify usability pain points via session recordings.
✅ Screenshots & Screen Recording Tools – Capture UX violations clearly.

2️⃣ Conducting the Heuristic Review

A. Review Using the Eight Golden Rules

Use the following structured table to assess usability issues:

Heuristic Principle User Journey Evaluation Criteria Assessment Notes Recommendations Severity (1-5) Screenshot Reference
Strive for Consistency Discovering a Cause Are UI elements consistent across screens?
Seek Universal Usability Navigating & Using Filters Are interactions accessible to different users?
Offer Informative Feedback Making a Donation Are users given clear confirmations for actions?
Design Dialogs to Yield Closure Tracking Donation Impact Are donation receipts & updates structured well?
Prevent Errors Cause Discovery & Search Are users prevented from making common mistakes?
Permit Easy Reversal of Actions Handling Unexpected Scenarios Can users undo actions easily?
Keep Users in Control Cause Selection & Donations Do users have clear navigation paths?
Reduce Short-Term Memory Load Trust Validation & Testimonials Are important details always visible?

B. Assign Severity to Each Issue

  • Severity Score = (Impact × Frequency) ÷ Ease of Fix
    • Impact (1-5): How bad is this issue for users?
    • Frequency (1-5): How often does it occur?
    • Ease of Fix (1-5): How difficult is it to fix?

🔹 Example: If users struggle with the donation process (Impact: 5), it occurs frequently (Frequency: 4), and is hard to fix (Ease: 2):
📊 Severity Score = (5 × 4) ÷ 2 = 10 (High Priority)

3️⃣ Linking Heuristic Findings to Real User Data

A. Use Research & Support Feedback

  • Add a column for related user feedback (from usability tests, customer support tickets, or FullStory session replays).
  • Example: “Users reported confusion in filtering causes due to inconsistent labeling.”

B. Tag Issues in GitLab

  • Labels: UX-Error, Trust-Issue, Navigation-Problem, Conversion-Blocker, etc.
  • Milestones: Link to sprint cycles or product updates.
  • Status Tracking: Open, In Progress, Fixed, Needs Validation.

4️⃣ Tracking & Reporting Heuristic Issues

A. Track Progress in GitLab

B. Automate Reports with CSV Exports

  • Download GitLab Issues CSV and filter by severity.
  • Use R/Python for trend analysis and visualization.
  • Example Report Metrics:
    • # of High Severity Issues vs. Fixed Issues Per Sprint.
    • Top UX Pain Points by Category (Navigation, Forms, Errors, etc.).

5️⃣ Next Steps & Continuous Improvement

✅ Prioritize UX Fixes in Roadmap – Assign high-severity issues to upcoming releases.
✅ Follow-Up Usability Testing – Validate fixes with another test cycle.
✅ Monitor SUPR-Q & NPS Trends – Assess whether UX fixes improve key metrics.
