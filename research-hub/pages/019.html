GA for Causes Usability Benchmark

Google Analytics instrumentation and research ops plan
Audience: UX and Engineering

Purpose

Connect the July 2025 Causes Usability Benchmark task set to concrete GA4 instrumentation and research outputs. Ensure every task has clear GA events, parameters, and 4D scorecard mapping so UX and Engineering can read, implement, and analyze consistently. The 4D frame is Delight, Doability, Desire, Dependability.

Scope

Applies to benchmark sessions run on staging or production with research tagging enabled. Covers Tasks 1 through 7 with event schemas, parameter dictionaries, computation notes, and reporting views. Survey items are captured by the in app survey system and linked to GA via shared session context and stable IDs.

Global conventions

Event names are lower snake case. Parameters are lower snake case. All tasks adopt the same subject IDs and session IDs. User properties for segmentation are set before task start.

User properties

  • donor_segment current_gen or next_gen
  • donor_history new or repeat
  • app_client web or ios or android
  • site_section causes
  • test_variant experiment label if present

Shared custom events

  • research_task_started task_id
  • research_task_completed task_id success true or false error_code optional
  • research_question_shown question_id location
  • research_question_answered question_id response_value response_text optional
    These are used in addition to feature events listed per task.

4D mapping quick guide
Doability covers time, success, errors.
Dependability covers CSAT, trust, SUS or SUPR Q subscales.
Delight covers emotion words and open comments.
Desire covers repeat use actions such as save favorite and referral.

Task 1

Discover and select a cause

Objective
Evaluate discovery including navigation, search, and filtering.

User facing instruction
Explore and select a cause that aligns with your values. Use search or filters as needed.

GA events to capture

  • research_task_started task_id t1_discover
  • select_cause cause_id cause_category entry_point
  • view_item cause_id cause_category
  • open_filter filter_name
  • apply_filter filter_name result_count
  • site_search query result_count optional if native search event exists
  • research_task_completed task_id t1_discover success true or false

Derived metrics

  • Task time start is research_task_started end is first select_cause that matches the instruction target
  • Task success true if a cause is selected and the participant confirms selection
  • Ease of use is captured by research_question_answered for the seven point item and linked to the task by task_id
  • Path analysis uses sequences of open_filter, apply_filter, and site_search before select_cause

4D mapping
Doability time and success
Dependability perceived ease
Desire save favorite if used in this step

Research readout

  • Median time to selection by segment
  • Share selecting via filters vs search vs navigation
  • Ease rating distribution with confidence intervals
  • Qual themes from open text for discovery choices

Task 2

Understand cause details and allocation

Objective
Assess comprehension of how donations are used and perceived clarity.

User facing instruction
Review the selected cause and focus on how your donation will be used.

GA events to capture

  • view_item cause_id cause_category
  • read_depth_percent value optional if instrumented
  • info_disclosure_shown element_id such as allocation_indicator or testimonial or banner
  • research_question_answered q_trust_confidence value 1 to 7
  • research_question_answered q_info_clarity value 1 to 7
  • research_task_completed task_id t2_details success true

Derived metrics

  • Time on page from first view_item to research_task_completed for t2_details
  • Trust confidence high share value 6 or 7
  • SUPR Q trust or clarity subitem distribution if used
  • Interaction with allocation components via info_disclosure_shown counts

4D mapping
Dependability trust and clarity
Delight perceived appearance trust if using SUPR Q trust subscale

Research readout

  • Lift in trust when allocation indicators are present
  • Clarity scores by cause category
  • Open text drivers of confidence

Task 3

Simulated donation and MWTP prompt

Objective
Simulate checkout and capture willingness to pay up to twenty five dollars post flow.

User facing instruction
Proceed as if donating. Complete the flow. Then answer the MWTP prompt.

GA events to capture

  • research_task_started task_id t3_checkout
  • begin_donation donation_flow single or recurring
  • select_amount amount_tier custom_amount frequency
  • add_donation_info payment_type
  • donation_complete donation_amount tier frequency
  • research_question_answered q_ease_checkout value 1 to 7
  • research_question_answered q_mwtp_absolute value numeric 0 to 25
  • research_task_completed task_id t3_checkout success true or false

Derived metrics

  • Task time from research_task_started to donation_complete or task end
  • Ease of use rating distribution
  • MWTP absolute distribution and median
  • Regression ready panel linking MWTP to ease, trust from Task 2, and design variant

4D mapping
Doability time and success
Dependability ease and confidence
Desire donation tier behavior and future intent proxy through MWTP

Research readout

  • Checkout time and ease by segment
  • MWTP medians and tails
  • Influence of allocation indicators from Task 2 on MWTP

Task 4

Navigate using filters

Objective
Evaluate category filter clarity and functional effectiveness.

User facing instruction
Use filters to find Education or Emergency Relief.

GA events to capture

  • research_task_started task_id t4_filters
  • open_filter filter_name
  • apply_filter filter_name result_count
  • select_cause cause_id cause_category
  • research_question_answered q_ease_filters value 1 to 7
  • research_task_completed task_id t4_filters success true or false

Derived metrics

  • Time on task from start to selection
  • Filter use sequences and success rates
  • Ease rating for filters

4D mapping
Doability time and success
Dependability perceived ease of filters
Desire save favorite actions if available

Research readout

  • Which filters reduce time most
  • Misleading labels or unused filters
  • Recommendations for copy and defaults

Task 5

Evaluate trust indicators and social proof

Objective
Assess how participants seek and interpret credibility cues.

User facing instruction
Before donating find reviews, testimonials, or other trust signals.

GA events to capture

  • trust_element_viewed element_type testimonial badge partner_logo review
  • trust_element_clicked element_id element_type
  • research_question_answered q_trust_overall value 1 to 7
  • research_question_answered q_nps_0_10 value 0 to 10
  • research_task_completed task_id t5_trust success true

Derived metrics

  • Trust score distribution
  • NPS distribution and computed NPS
  • Heatmap of trust elements viewed and clicked before begin_donation

4D mapping
Dependability trust and NPS
Delight spontaneous comments if collected as open text

Research readout

  • Which trust elements correlate with higher trust and with donation start
  • Placement and copy improvements for high performing signals

Task 6

Catch trial search for a non existent cause

Objective
Evaluate resilience and recovery in a controlled failure.

User facing instruction
Search for clean water access in urban communities. This does not exist.

GA events to capture

  • site_search query result_count
  • no_results_shown query suggested_count
  • suggestion_clicked suggestion_type cause_id optional
  • rage_click flag true with element_id if collected
  • research_question_answered q_difficulty_no_results value 1 to 7
  • research_question_answered q_recovery_open response_text
  • research_task_completed task_id t6_catch success based on recovery rules

Derived metrics

  • Time to recovery or abandonment
  • Frustration markers rage clicks looping navigation
  • Use of suggested alternatives

4D mapping
Doability error handling
Dependability difficulty perception
Desire whether users continue exploring after failure

Research readout

  • Best performing fallback patterns
  • Copy changes for zero results states
  • Filter or taxonomy adjustments

Task 7 optional

Post donation feedback and follow up

Objective
Assess emotional closure and follow up engagement opportunities.

User facing instruction
Check the confirmation or thank you. Look for share or update options.

GA events to capture

  • donation_complete donation_amount tier frequency
  • confirmation_seen confirmation_template_id
  • share_referral_clicked channel
  • updates_opt_in_clicked update_type email or sms
  • research_question_answered q_csat_confirmation value 1 to 7
  • research_task_completed task_id t7_follow_up success true

Derived metrics

  • Confirmation engagement rate
  • CSAT on confirmation
  • Share and updates opt in rates

4D mapping
Dependability CSAT
Delight emotion words in open comments
Desire shares and opt ins

Research readout

  • Which confirmation templates drive higher CSAT and shares
  • Recommended copy and layout for gratitude and next steps

Data model and joins

  • Each research task has a unique task_id and is bracketed by research_task_started and research_task_completed
  • Survey answers use research_question_answered with stable question_id codes so the same metrics can be repeated over time
  • Behavioral events are joined by session and timestamps to create task level panels for analysis
  • For segment analysis set donor_segment and donor_history user properties at session start

QA plan

  • Validate event firing with GA4 DebugView for every task path
  • Check parameter presence and types against the event dictionary
  • Confirm timing windows measure start and end correctly
  • Verify suppression rules for intercept prompts if any study prompts are used

Reporting views

UX research dashboard

  • Per task time, success, ease, trust, CSAT
  • Heatmaps for filter and trust element interactions
  • Open text themes linked to task outcomes

Product and engineering dashboard

  • Funnel from view_item to donation_complete with filter and trust interactions
  • Zero results frequency and recovery rates
  • Confirmation engagement and downstream repeat visit indicators

Alignment with the 4D scorecard

The above instrumentation feeds all four 4D buckets for the Causes experience and supports executive friendly reporting

  • Doability measures are time, success, and errors at the task level
  • Dependability measures are confidence, CSAT, and NPS where applicable
  • Delight measures are feeling scale words and open comments on experience quality
  • Desire measures are referral clicks, save favorite, and repeat behaviors over time

Notes:

  • Keep question wording stable and reference by question_id so we can trend
  • Use the same seven point scales across tasks for ease, trust, and CSAT to simplify analysis
  • When running experiments, log ab_variant at session start and on first task event so variant assignment is unambiguous
