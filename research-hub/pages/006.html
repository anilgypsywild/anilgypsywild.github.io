MaxDiff: End-to-End Script (README)

This note explains what the script does, how it works, how to run it, and how to customize it. It’s written for PM/stakeholders as well as anyone who may maintain the code later.

What this script does

  • Builds a near-balanced MaxDiff design (items per screen × screens per respondent × versions).
  • Simulates survey responses for a synthetic sample with 3 segmentation axes (age, donor type, giving status).
  • Converts each screen’s Best/Worst choice into pairwise comparisons.
  • Estimates item utilities with a [name omitted]–[name omitted] / logistic model (no intercept, difference coding).
  • Converts utilities to 0–100 relative importance.
  • Repeats estimation by segment to compare audiences.
  • Generates a small set of publication-ready plots.

All randomization uses set.seed(42) for reproducibility.

Quick start

Prerequisites

  • R (any recent version).
  • The script only uses base R + common tidyverse plotting packages already loaded in the file (ggplot2, dplyr, forcats, stringr, tibble).

Run it

  1. Put the script in a project folder.
  2. Create a plots/ subfolder (the script writes PNGs there).
  3. source("maxdiff_end_to_end.R") in R/RStudio, or run the file line-by-line.

Outputs (files)

The script saves the following images in plots/:

  • 01_plot_RelImpBarChart.png – Overall relative importance bar chart
  • 02_plot_ClusterLevelImportance.png – Cluster-level (theme) importance
  • 03_plot_SegmentCompareNGCG.png – NextGen vs CurrentGen (top 10)
  • 04_plot_SegmentHighImpactVsCasual.png – High-impact vs Casual (top 10)
  • 05_plot_SegmentFirstTimeVsRepeat.png – First-time vs Repeat (top 10)
  • 06_plot_RankHeatMap.png – Rank heat map across segments

Parameters you may change

  • Item bank: edit the items <- c(...) vector.
  • Design size:
    • K – items per screen (default 5)
    • Tsets – screens per respondent (default 12)
    • V – number of design versions (default 5)
  • Sample size & composition: see N and the distributions for age, donor_type, and giving_status.
  • Segment effects: edit the seg_effect() function to reflect expected preferences.

How it works (step by step)

1) Design construction

  • Function: make_design(items, K, Tsets, V)
  • Greedy balancing: items with lower placement counts are more likely to be sampled next, keeping exposure roughly even across items, screens, and versions.
  • Output: design is a list of versions, each a list of screens (character vectors of K items).

Tip for survey programming: print_design_for_forms() prints each screen per version in a copy-paste friendly format.

2) Simulating respondents

  • We create N = 100 synthetic respondents with attributes:
    • age ∈ {18–34, 35+}
    • donor_type ∈ {HID, Casual}
    • giving_status ∈ {FirstTime, Repeat}
  • Utilities for each item are built as:
    u = u_base + seg_effect(age, donor_type, giving_status)
    then centered per-respondent.

3) Turning Best/Worst into pairwise rows

For each screen:

  • Choose best = argmax utility, worst = argmin utility (with noise).
  • Create pairwise wins for:
    • best vs each “other”
    • each “other” vs worst
    • best vs worst
      This yields the usual MaxDiff pair set consistent with a [name omitted]–[name omitted] formulation.

4) Design matrix (difference coding)

  • We fit a logistic regression with no intercept (-1), using difference coding:
    • Columns are all items except the reference (the last item in items).
    • For each pair (winner, loser) we set +1 for the winner’s column and –1 for the loser’s column when the item is not the reference.
  • The reference item’s coefficient is implicitly zero.
  • We then reconstruct the full 15-item vector by inserting the reference at 0 and mapping coefficients back to original item names (backtick/syntactic name safe).

5) Estimation (overall)

  • Fit: glm(y ~ . - 1, family = binomial(), data = cbind(y, X))
  • Center utilities and rescale to 0–100 relative importance.
  • Output: overall_table (item, centered utility, importance).

6) Estimation (segments)

  • Segment membership is stored as named logical vectors keyed by respondent_id, e.g.
    idx_nextgen <- setNames(resp$age == "18-34", resp$respondent_id)
  • Function: estimate_segment(filter_idx, label)
    • Subsets pairwise rows by respondent_id %in% seg_ids.
    • Rebuilds the exact same difference-coded design matrix.
    • Fits the same logistic model, inserts the reference at 0.
    • Centers and rescales to 0–100.
    • Returns a tidy table (segment, item, utility, importance), safely de-duplicated and consistently labeled.

This function was hardened to avoid common pitfalls: NA/renamed columns, perfect separation in small segments, and label duplication caused by backticks/syntactic names.

7) Plotting

All charts are built from the already-cleaned tables. They:

  • Order factors for readability.
  • Use value labels and slim bar widths where appropriate.
  • Include a cleaned, two-line legend on top for side-by-side segment charts.
  • Wrap long y-axis labels and rotate x-axis labels to avoid collisions.

Adapting to real survey data

If you export Best/Worst choices from Google Forms or Qualtrics, replace only the simulation step:

  1. Load your responses into a choices data frame with columns:

    • respondent_id, version (optional), screen_id, best, worst

  2. (Optional but recommended) run the built-in QC:

    check_same_choice(choices) # flags screens where best == worst

  3. Keep the rest of the pipeline unchanged:

    • build_pairs() → pairs_all
    • Build X with make_X()
    • Fit overall and segments the same way.

As long as item text matches items exactly (or you map your labels to that vector), the downstream estimation and plots will work unchanged.

Directory structure (suggested)

maxdiff-project/ ├─ maxdiff_end_to_end.R ├─ data/ # (optional) put raw survey exports here ├─ plots/ # all PNG outputs are written here └─ README.md # this file

Troubleshooting

  • All importance values are identical or zero
    • Check that X was created with check.names = FALSE so columns aren’t silently renamed.
    • Ensure at least some variation in choices; identical choices/noise → flat results.
  • Segment table comes back NULL
    • The segment may be too small (nrow(sub_pairs) < 50) or exhibits perfect separation. Increase sample or relax the cutoff.
  • Duplicated/garbled item labels
    • Always pass labels through clean_item() before distinct/filter/joins.
    • The script already unifies backticked/syntactic names back to the original strings.
  • “object 'sub_pairs' not found”
    • sub_pairs is intentionally scoped inside estimate_segment(). Don’t reference it outside; use the function’s return value instead.

Glossary (plain-English)

  • MaxDiff (Best–Worst): A survey technique where respondents see a small set of items per screen and pick the most and least important. It’s efficient for ranking many items with fewer questions.
  • [name omitted]–[name omitted] model: A pairwise comparison model. In our setup, Best–Worst choices are converted into win/loss pairs and fitted via logistic regression.
  • Difference coding: Represents each pair as +1 for the winner, –1 for the loser (w.r.t. a reference item), enabling a no-intercept logistic regression.
  • Relative importance (0–100): Utilities are centered and linearly rescaled to an easy-to-read 0–100 scale.

Change log (what we fixed while hardening the script)

  • Robust mapping of glm coefficient names back to original item labels (handles backticks/syntactic names).
  • X/Xs are created with check.names = FALSE so column names remain exactly the original item strings.
  • estimate_segment() now:
    • Indexes segment rows deterministically via %in% on respondent_id.
    • Guards against NA coefficients and separation.
    • De-duplicates labels after cleaning.
  • Centralized clean_item() to ensure plots and tables never duplicate items due to stray backticks/spaces.
  • Plot aesthetics standardized (readable axes, wrapped labels, compact legends).

# 2. Build a near-balanced design across versions
# Greedy balance: keep counts per item near equal across all screens in all versions
make_design <- function(items, K, Tsets, V) {
  counts <- setNames(rep(0L, length(items)), items)
  design <- list()
  for (v in 1:V) {
    screens <- vector("list", Tsets)
    for (t in 1:Tsets) {
      # sample with bias toward lower counts to keep balance
      w <- max(counts) + 1 - counts
      pick <- character(0)
      pool <- items
      cc <- counts
      for (i in 1:K) {
        w <- max(cc) + 1 - cc
        probs <- w / sum(w)
        choice <- sample(pool, 1, prob = probs)
        pick <- c(pick, choice)
        idx <- match(choice, names(cc))
        cc[idx] <- cc[idx] + 1L
        pool <- setdiff(pool, choice)
        cc <- cc[names(cc) %in% pool]
      }
      screens[[t]] <- pick
      counts[names(counts) %in% pick] <- counts[names(counts) %in% pick] + 1L
    }
    design[[v]] <- screens
  }
  design
}


design <- make_design(items, K, Tsets, V)

# 5. Create choice data from design for each respondent
library(stats)
make_choices <- function(design, resp_row, items, u_base, noise_sd = 0.15) {
  v <- resp_row$version
  screens <- design[[v]]
  eff <- seg_effect(resp_row$age, resp_row$donor_type, resp_row$giving_status)
  u <- u_base + eff
  # center
  u <- u - mean(u)
  rows <- list()
  rid <- resp_row$respondent_id
  for (t in seq_along(screens)) {
    set_items <- screens[[t]]
    util <- u[set_items] + rnorm(length(set_items), 0, noise_sd)
    best <- set_items[which.max(util)]
    worst <- set_items[which.min(util)]
    rows[[length(rows) + 1]] <- data.frame(
      respondent_id = rid,
      version = v,
      screen_id = t,
      best = best,
      worst = worst,
      stringsAsFactors = FALSE
    )
  }
  do.call(rbind, rows)
}
choices <- do.call(rbind, lapply(1:nrow(resp), function(i) make_choices(design, resp[i,], items, u_base)))


build_pairs <- function(choices_row, design) {
  v <- choices_row$version
  t <- choices_row$screen_id
  set_items <- design[[v]][[t]]
  best <- as.character(choices_row$best)
  worst <- as.character(choices_row$worst)
  others <- setdiff(set_items, c(best, worst))
  pairs <- list()
  for (o in others) pairs[[length(pairs)+1]] <- c(best, o, 1)
  for (o in others) pairs[[length(pairs)+1]] <- c(o, worst, 1)
  pairs[[length(pairs)+1]] <- c(best, worst, 1)
  mat <- do.call(rbind, pairs)
  df <- data.frame(winner = mat[,1], loser = mat[,2], y = as.numeric(mat[,3]), stringsAsFactors = FALSE)
  df$respondent_id <- choices_row$respondent_id
  df$version <- v
  df$screen_id <- t
  df
}

make_X <- function(winner, loser, item_cols) {
  x <- rep(0, length(item_cols)); names(x) <- item_cols
  if (winner %in% item_cols) x[winner] <- x[winner] + 1
  if (loser %in% item_cols) x[loser] <- x[loser] - 1
  x
}

# Map any glm coefficient name (raw, backticked, or syntactic) back to the original item string
map_to_original <- function(nms, items) {
  # 1) strip backticks from glm names
  n1 <- gsub("^`|`$", "", nms)
  # 2) try direct match to originals
  out <- items[match(n1, items)]
  # 3) for any still NA, try matching syntactic (dotified) versions
  idx <- is.na(out)
  if (any(idx)) {
    syn <- make.names(items)
    out[idx] <- items[match(n1[idx], syn)]
  }
  out
}

# Clean item text once so backticks / extra spaces don't create duplicates
clean_item <- function(x) {
  x <- trimws(x)
  x <- gsub("^`+|`+$", "", x)
  x <- gsub("\\s+", " ", x)
  x
}

estimate_segment <- function(filter_idx, label) {
  # 1) get respondent ids for this segment
  seg_ids <- ids_from_idx(filter_idx)
  if (length(seg_ids) == 0L) return(NULL)

  # 2) subset pairs deterministically (no NA-logical indexing)
  sub_pairs <- pairs_all[pairs_all$respondent_id %in% seg_ids, , drop = FALSE]
  if (!nrow(sub_pairs)) return(NULL)

  # 3) build segment X with exact item column names, kept verbatim
  Xs <- t(apply(
    sub_pairs[, c("winner","loser")], 1,
    function(r) make_X(r[1], r[2], item_cols)
  ))
  Xs <- as.data.frame(Xs, check.names = FALSE)  # DO NOT let R rename columns
  ys <- sub_pairs$y

  # 4) fit (a little more robust control)
  fit <- glm(ys ~ . - 1, family = binomial(), data = cbind(ys, Xs),
             control = list(maxit = 50))
  co <- coef(fit)
  if (is.null(co)) {
    # fallback: cannot estimate segment (too sparse / perfect separation)
    return(NULL)
  }
  co[is.na(co)] <- 0  # guard against rare NA coefficients

  # 5) map coefs back to full item vector using the same naming as overall
  uh <- setNames(rep(0, length(items)), items)
  uh[names(co)] <- co
  uh[ref_item] <- 0

  # 6) center, scale to 0–100
  uh <- uh - mean(uh)
  rng <- max(uh) - min(uh)
  imp <- if (rng > 0) (uh - min(uh)) / rng * 100 else rep(0, length(uh))

  # 7) output with de-duplicated, cleaned item labels
  out <- data.frame(
    segment   = label,
    item      = clean_item(names(uh)),
    utility   = round(as.numeric(uh), 4),
    importance= round(as.numeric(imp), 2),
    stringsAsFactors = FALSE,
    row.names = NULL
  )
  # in case any accidental duped labels slipped through, keep the highest-importance copy
  out <- out[order(out$item, -out$importance), ]
  out <- out[!duplicated(out$item), ]

  # sort by importance high→low for readability
  out[order(-out$importance), ]
}

# 12. Helper to detect bad screens where a respondent chose the same item as best and worst
# If you import real data from Forms, run this check and drop offenders per screen
