Google Analytics Instrumentation Plan for In-App Intercept Surveys

Focus: Capturing intercept survey data natively in Causes and linking it to donor behavior

1. Purpose

To enable in-app intercept surveys to capture trust, clarity, and satisfaction signals directly inside Causes, and link these self-reports to observed donor behavior in GA4. This gives us a unified dataset for testing design hypotheses about Current Gen donors.

2. Instrumentation Requirements

A. Survey Triggering

  • Confirmation page intercept: Trigger after successful donation, once per user per 2 weeks.
  • Cause detail intercept: Trigger if user dwells ≥60s or navigates away without donating.
  • No results intercept: Trigger once per week on first no-results query.

B. GA Event Lifecycle

Event Parameters Description
survey_shown location (confirmation, cause_detail, no_results) question_set_id Fires when survey is presented
survey_started location, question_set_id Fires when user interacts with first survey element
survey_response location, question_id, response_value Fires for each answered question
survey_completed location, question_set_id, completion_status Fires when survey is submitted or abandoned
donation_complete (existing GA4 purchase) amount, tier, frequency Links survey to transaction data
filter_applied filter_name, result_count Links survey answers to discovery behaviors
no_results_shown query, suggested_count Connects frustration states to survey responses

C. User Properties

  • donor_segment: Current Gen vs Next Gen
  • donor_history: new vs repeat donor
  • test_variant: A/B assignment (allocation indicator, confirmation copy, etc.)

3. Data Handling

  • Each survey_completed event generates a survey_id stored in GA4 and mirrored in the app’s DB.
  • Daily ETL job exports GA4 events + survey DB to warehouse.
  • Research joins survey responses to behavioral metrics (time on task, tier choice, referral clicks).

4. Research Alignment with CVG 4D Scorecard

  • Doability: Donation completion, time on task, error rates.
  • Dependability: Confidence ratings, CSAT, NPS (from survey).
  • Delight: Emotion word scales, open text (survey_response).
  • Desire: Repeat donations, referral shares, save favorite.

5. Engineering Next Steps

Week 1

  • Define GA event schema for survey_shown, survey_response, survey_completed.
  • Add survey question/answer IDs to the app’s data layer.

Week 2

  • Implement GA4 custom events in app code.
  • Set up DebugView QA to ensure event firing and parameter integrity.

Week 3

  • Deploy intercepts to staging. Validate:
    • Confirmation survey only after successful donation.
    • Cause detail dwell ≥60s.
    • No results intercept triggers correctly.

Week 4

  • Connect GA4 event exports with survey DB.
  • Test join queries linking survey responses to donation outcomes.

Week 5

  • Provide research with joined dataset for first analysis.
  • Engineering documents schema and ownership for long-term maintenance.

6. Deliverables

  • GA4 custom event schema and data layer mapping.
  • Staging validation log with DebugView screenshots.
  • Automated warehouse export + join with survey DB.
  • Final engineering handoff document for research.

End of Doc
