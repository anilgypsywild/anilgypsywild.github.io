Google Analytics Event Schema for In App Intercept Surveys

Engineering centric specification for Causes Current Gen study

Purpose

Define a complete GA4 event schema and data layer contract for in app intercept surveys, so research can link survey responses to donor behavior and 4D outcomes.

Scope

Applies to Causes web and app clients that present in app intercept surveys at confirmation, cause detail, and no results states. Covers GA4 events, parameters, user properties, trigger rules, validation, and warehouse joins.

Trigger rules for in app intercept

  1. Confirmation location
    Fire survey_shown three seconds after donation_complete. Suppress if a survey_completed with location confirmation exists in the last fourteen days for this user_id or device_id.
  2. Cause detail location
    Fire survey_shown at dwell time sixty seconds or on exit intent. Suppress if confirmation survey fired in the last fourteen days.
  3. No results location
    Fire survey_shown on the first zero results event per user per seven days.
  4. Never show more than one intercept per session.
  5. survey_started only after the first interaction inside the survey container.

Data layer contract

Provide a documented data layer object that the analytics SDK reads at the time of each event.

Example payload for survey_response

{ "event": "survey_response", "location": "confirmation", "question_set_id": "cg_trust_v1", "question_id": "q_confidence_01", "response_value": 6, "item_id": null, "user_properties": { "donor_segment": "current_gen", "donor_history": "repeat", "ab_experiment": "alloc_proof_v1", "ab_variant": "treatment_a", "app_client": "web", "site_section": "causes" } }

Validation checklist

Engineering should validate in GA4 DebugView and network logs

  1. Event names match the taxonomy exactly
  2. Required parameters are present for each event type
  3. Parameter types are correct
  4. Suppression logic works and no duplicate surveys occur
  5. donation_complete revenue events remain accurate and unaffected
  6. User properties populate before the first survey event

Warehouse model and joins

Daily export GA4 events to the warehouse. Persist survey form data in the application database. Join strategy

  1. Join on session id and event time window for survey_started to donation_complete for confirmation flows
  2. For per question analysis use survey_response grouped by question_id and joined to behavioral events within the same session
  3. Create derived tables
    a. current_gen_trust_panel aggregated by question_id and response_value
    b. donation_tier_shift_by_variant aggregated by amount_tier and ab_variant
    c. confirmation_csat_lift aggregated by location and completion_status

Security and privacy

No personal information is sent as event parameters. Respect consent choices before firing survey events. Keep question wording in the app database and reference by stable IDs.

Notes for research alignment with 4D

Doability uses donation completion, time on task, and error rates captured by existing events.
Dependability uses confidence ratings and CSAT collected through survey_response and survey_completed.
Delight uses emotion words and open text from survey_response.
Desire uses repeat donations, save favorite, and share referral clicks tied to user properties and custom events.
