Causes App Heuristic Review Template

  • This heuristic review template is designed for Researchers, to systematically evaluate Causes App usability.
  • The review aligns with Ben Shneiderman’s Eight Golden Rules and is structured based on critical user journeys from the platform.

Instructions for Review

  • Review each section in the Causes App and assess against the Eight Golden Rules.
  • Document any violations, usability pain points, and recommendations.
  • Focus on discoverability, trust, navigation, and donation flows.
  • Provide screenshot references where applicable.

Heuristic Review Criteria

1️⃣ Strive for Consistency

  • Are UI elements (buttons, typography, colors) consistent across different screens?
  • Are navigation patterns and actions uniform (e.g., donation flows, filtering causes)?
  • Does terminology remain the same (e.g., ‘Donate’ vs. ‘Give’)?

💡 Recommendations:

2️⃣ Seek Universal Usability

  • Does the app accommodate different user types (new vs. returning donors, accessibility needs)?
  • Are key interactions optimized for both mobile and desktop experiences?
  • Is font size, contrast, and readability appropriate for all users?

🔍 Assessment Notes:

💡 Recommendations:

3️⃣ Offer Informative Feedback

  • Does the system provide clear confirmation messages after actions (e.g., donation confirmation, filter selections)?
  • Are errors clearly indicated with solutions (e.g., invalid payment details)?
  • Does the app use visual feedback (loading states, success indicators)?

🔍 Assessment Notes:

💡 Recommendations:

4️⃣ Design Dialogs to Yield Closure

  • Are important user actions (donation, cause selection) structured with clear start, middle, and end states?
  • Is there a confirmation or summary after completing a donation?
  • Does the user receive meaningful updates post-donation?

🔍 Assessment Notes:

💡 Recommendations:

5️⃣ Prevent Errors

  • Does the system prevent common errors (e.g., disabling ‘Donate’ until required fields are completed)?
  • Are filtering and sorting functions designed to minimize irrelevant results?
  • Does the app avoid accidental actions (e.g., confirming before deleting payment details)?

🔍 Assessment Notes:

💡 Recommendations:

6️⃣ Permit Easy Reversal of Actions

  • Can users undo unintended actions (e.g., removing a cause from favorites, canceling a donation)?
  • Are there clear ‘Back’ or ‘Cancel’ options on critical screens?
  • Does the app confirm before irreversible actions (e.g., deleting saved payment info)?

🔍 Assessment Notes:

💡 Recommendations:

7️⃣ Keep Users in Control

  • Are users able to navigate freely without being forced into predefined paths?
  • Are donation settings customizable (e.g., recurring vs. one-time donation)?
  • Do users feel in control over their experience (e.g., stopping email notifications, adjusting impact updates)?

🔍 Assessment Notes:

💡 Recommendations:

8️⃣ Reduce Short-Term Memory Load

  • Are important details (selected cause, donation amount, progress updates) always visible?
  • Are forms designed to minimize repetitive entry (e.g., saved payment details, suggested amounts)?
  • Does the app avoid forcing users to recall information between screens?

🔍 Assessment Notes:

💡 Recommendations:

User Journey-Specific Evaluations

🔎 Discovering a Cause

  • Are search & filtering options intuitive?
  • Is cause information clear and easy to compare?

💡 Understanding Cause Details & Transparency

  • Are donation allocation details visible?
  • Is impact tracking easily accessible?

💳 Making a Donation

  • Is the checkout process simple and friction-free?
  • Are there error prevention measures (e.g., detecting expired credit cards)?

🔄 Tracking Donation Impact

  • Are post-donation updates meaningful?
  • Do users feel engaged after donating?

⚠️ Handling Unexpected Scenarios (Catch Trial)

  • How does the system handle missing or incorrect data entries?
  • Is there useful error messaging for unsupported searches?

Final Deliverables

  1. Key usability violations found in each heuristic.
  2. Screenshots where applicable.
  3. High-priority recommendations for platform improvement.

Output Format:

📂 Final Heuristic Review Report → To be shared with UX and Product team.
